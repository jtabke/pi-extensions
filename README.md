# pi-extensions

Personal [Pi](https://github.com/earendil-works/pi-mono) extensions shared across clients.

## Extensions

### `auto-session-name`

Names an unnamed native Pi session from its first nonempty user text at `message_end`, without waiting for or blocking the assistant. An `agent_settled` fallback handles already-recorded user text. It checks the automatic title at settlement after 5 additional nonempty user turns, then every 5 on the active branch. The naming prompt requests the exact current title for minor changes or related subtasks, and a new title only when a different topic clearly becomes the focus. Automatic ownership and the next check are stored in a non-context session entry, so refinement resumes after reopening. Manual names and manual clearing remain protected across restarts. Existing titles without ownership metadata—including titles generated by older versions—remain untouched. Naming is disabled until you explicitly select an authenticated model; it never falls back to the session model.

```text
/auto-name-model provider/model-id
/auto-name-model
/auto-name-model status
/auto-name-model off
```

Run `/auto-name-model` without arguments to open a list of authenticated models. Escape leaves the saved choice unchanged. If no authenticated models are available, the command suggests `/login`. Without an interactive UI, the no-argument command reports status instead. `/auto-name-model status` always reports the current choice.

Model IDs can contain `/`. The command validates the model and configured authentication before saving. Selection does not send a request; the next nonempty user message or settled boundary may try. Each session instance gets one initial naming attempt, with another permitted after explicit model selection. Refinement failures keep the title and wait for the next 5-turn interval. Status reports the current choice.

The global file is `getAgentDir()/extensions/auto-session-name.json` (normally `~/.pi/agent/extensions/auto-session-name.json`). Its only fields are `{"provider":"provider-id","model":"model-id"}`; `off` writes `{"provider":null,"model":null}`. Missing or invalid configuration disables naming; invalid configuration warns and is not repaired automatically. No credentials or transcripts are stored there.

Privacy: initial naming sends only up to 1600 characters of the first nonempty user text on the active branch to the selected provider. Refinement sends the current title and the most recent 10 nonempty user/assistant text messages, capped at 1600 characters per user message and 800 per assistant message. Each scheduled check sends a request even if the model keeps the title. Tools, thinking, images, and metadata are excluded. The request has a 15-second limit, 96 output tokens, no retries, and no prompt-cache retention. The title is capped at 80 characters. Pi persists the title; the extension also records ownership and the next refinement turn in custom session entries. History filenames and session IDs do not change. Existing and in-flight manual names are protected. Session replacement, shutdown, name changes, and explicit model changes cancel this extension's request; stale results cannot name a replacement session.

Validated against installed Pi **1.0.0**, not the repository's older development SDK. Focused tests use Node **26.5** and isolated configuration, with no provider calls:

```bash
node --experimental-test-module-mocks --test extensions/auto-session-name/index.test.ts
```

Focused strict type validation uses TypeScript 5.9.3 with a temporary out-of-repository tsconfig: `strict`, `noEmit`, `skipLibCheck`, `target: ES2023`, `module: ESNext`, `moduleResolution: Bundler`, `allowImportingTsExtensions`, Node types, and a `paths` mapping of `@earendil-works/pi-coding-agent` to the installed 1.0.0 `dist/index.d.ts`. Include only this extension and test, then run `tsc -p /path/to/temporary/tsconfig.json`. No dependencies were upgraded and no installation was performed. Fully restart Pi after owner-approved activation changes.

### `fast`

Adds `service_tier: "priority"` to enabled ChatGPT-authenticated OpenAI Codex requests. Run `/fast` to open a configuration menu for:

- One list of parent models with saved On/Off settings, marking the current parent. Unavailable saved models can be disabled.
- The subagent-wide On/Off setting.

Menu changes and inline On/Off commands save immediately and persist across sessions; they are not temporary overrides. Escape cancels the open selection; it does not undo earlier changes. With no saved configuration, Luna is on, other parent models are off, and the subagent-wide setting is off. Priority service may increase quota usage or cost.

Manually registered Codex models, including `gpt-6.1-sol`, appear in the menu when ChatGPT authentication is available. Select the model in Pi, then run `/fast on` to save its Fast setting. No extension model-list update is needed.

Inline controls remain available, including without an interactive UI:

```text
/fast on
/fast off
/fast status
```

`/fast status` reports both the current model and subagent settings. Control both together with:

```text
/fast all on
/fast all off
/fast all status
```

Control Luna explicitly through the same command:

```text
/fast luna
/fast luna off
/fast luna status
```

Enable Fast mode as the default for every supported native `pi-subagents` workflow child:

```text
/fast subagents on
/fast subagents off
/fast subagents status
```

The subagent toggle adds `fast: true` to inline `workflowScript` launches that do not already set `fast`. Explicit `fast: true` and `fast: false` values are preserved; turning the default off does not force launches off. Fast mode supports only the native OpenAI Codex models allowed by `pi-subagents`; external runners and unsupported models fail through its normal validation.

Fast mode settings are stored in `~/.pi/agent/extensions/fast.json`. On startup, the extension migrates the former `luna-fast.json` file automatically. The old `{ "enabled": boolean }` format remains compatible and controls Luna only. Models from other providers and non-ChatGPT authentication do not support this extension's parent-session Fast mode. The machine-local setting is not stored in this repository.

Focused Fast extension tests (requires Bun):

```bash
bun test tests/fast.test.ts
```

### `notify`

Sends a native notification when the parent Pi session finishes an agent turn and waits for input. Subagent processes do not send notifications.

```text
/notify-toggle [on|off|status]
/notify-test [message]
/notify-min [seconds|off|status]
```

Settings are stored in `~/.pi/agent/notify-settings.json`. The default is enabled with no minimum turn duration. Debug output is written to `~/.pi/agent/notify-debug.log`. macOS uses `terminal-notifier` when available and falls back to `osascript`; Windows uses a toast notification; Kitty and other terminals use terminal notification escape sequences.

### `ollama-auto-models`

Discovers models from a local Ollama server at startup, registers them as the `ollama` provider, and refreshes them with:

```text
/ollama-refresh
```

The server is read from `OLLAMA_BASE_URL` or `OLLAMA_HOST` and defaults to `http://localhost:11434`. The extension also supports these environment variables:

- `PI_OLLAMA_DISCOVERY_TIMEOUT_MS` — discovery timeout; default `1500`.
- `PI_OLLAMA_CONTEXT_WINDOW` — registered context window; default `32768`.
- `PI_OLLAMA_MAX_TOKENS` — registered maximum output tokens; default `8192`.
- `PI_OLLAMA_TOOLS` — comma-separated active tools for Ollama models; default `read,edit,write,bash`.
- `PI_OLLAMA_LEAN_TOOLS` — set to `0`, `false`, `off`, or `no` to disable tool filtering.
- `PI_OLLAMA_THINKING` — thinking level override; default `keep` (inherit).

Ollama discovery is best-effort. A running Ollama service is not required for Pi to start.

### `openai-usage`

Shows OpenAI Codex OAuth rate-limit windows in the Pi status area and refreshes them after agent turns and model changes.

```text
/openai-usage
```

The extension reads the `openai-codex` provider credential from Pi. Run `/login openai-codex` if the credential is unavailable. It queries the ChatGPT usage endpoint every 60 seconds while an OpenAI Codex model is active. It does not display usage for other providers.

Machine-local settings and credentials for all extensions remain outside this repository. They are not stored here.

## Install

Local development checkout:

```bash
pi install ~/Documents/Coding/pi-extensions
```

Another client:

```bash
pi install git:git@github.com:jtabke/pi-extensions
```

After changing installed extensions, restart Pi.
